# Domain glossary

- **Design source**: The current uploaded artwork that owns carpet outline, motif topology, spatial relationships, and default colour regions.
- **Material reference**: The umbrella term for real visual evidence about a carpet construction; it has no current-pattern or colour authority.
- **Construction reference**: A material reference used only for yarn geometry, interlacing, density, relief, finish, thickness, or edge construction.
- **Paired mapping example**: An exact historical trio containing a design source and its corresponding real product overview and material detail. It teaches how artwork becomes that construction, not what the current motif or colours should be.
- **Scene style reference**: A product photograph used only for camera, lighting, background, crop, and presentation.
- **Quality anchor**: An approved generated sample used only as a secondary target for visual polish.
- **Material profile**: An editable generic description of one carpet construction family.
- **Material library entry**: A packaged material definition, manifest, and durable real or derived reference assets.
- **Construction lock**: The supported construction, yarn geometry, organisation, scale behaviour, relief, finish/light response, boundary behaviour, and edge geometry applied consistently to both outputs.
- **Backend strategy**: The single reference-grounded generation path, or an external-execution packet when the current environment cannot create images.
- **Anti-substitution**: A material-identity rejection condition used to catch a visually different construction such as print, fur, chunky knit, or block texture.
- **Render lock**: The complete per-run record containing material, construction lock, colour authority, mapping mode, camera, edge treatment, backend, and deliverables.
- **Detail corner**: The fixed `lower_left` corner in the upright design-source coordinate frame, shared by both outputs. Its detail output contains the complete corner junction, both bound exterior edges, nearby motif, and a meaningful plain-field area.
- **Material detail**: A close contextual view of the selected corner showing the binding junction, both adjacent edges, recognisable border artwork, yarn or pile, relief, and colour transitions.
- **Product overview**: A near-overhead, flat-laid product-record view with mild near-to-far perspective, used to judge outline, motif layout, colour relationships, edge treatment, and overall material read; the complete rug should fill about 92–96% of the frame with all four corners and the bound outline visible. It is not a lifestyle or furnished-room image.
- **Visual consistency**: Both outputs express one construction system at different camera distances without claiming identical pixels.
- **Visual sample**: A screening artifact for product review, distinct from a manufacturing approval or physical standard.
- **Calibrated construction**: The one confirmed low-relief, tightly woven and bound carpet construction that this skill renders in the current phase. Its project name is **Wilton flatweave**; this name identifies the project's target construction and is not a claim about unobserved manufacturing specifications.
- **Verified paired mapping set**: One artwork, its matching physical product overview, and its matching physical detail, all confirmed to represent the same product and calibrated construction. The project currently has three such sets.
- **Detail-first lightweight check**: The automatic inspection after the material-detail output is generated and before the product overview is generated. Visual caveats are recorded; only a missing, unreadable, or technically invalid output stops the sequence.
- **Colour authority**: The uploaded current artwork owns every current colour region. The renderer may apply a construction-calibrated global photographic response, but paired physical examples may not contribute their palette or motif colours.
- **Leave-one-out calibration**: The validation method that derives Wilton-flatweave rendering parameters from two verified paired mapping sets, then judges whether they reproduce the third set without using it as a rendering reference.
